# JSON 语法基础

> 本篇作者：pardon

---

## JSON 到底是什么？

你可以把 JSON 简单理解成 一张“填好的表格”。

比如下面这段 JSON 代码：

```json
{
  "name": "田所浩二",
  "age": 24,
  "isStudent": true
}
```

它对应的表格就是：

| 姓名 | 田所浩二 |
| --- | --- |
| 年龄 | 24 |
| 学生 | 是 |

所以，写 JSON 本质上就是在填表格——

冒号 左边 是 键（key），相当于表格里的“项目名称”（如姓名、年龄）；

冒号 右边 是 值（value），也就是我们要填写的“具体内容”。

---

## 值的类型有哪些？（⚠️ 重点！）

JSON 里的“值”只能是以下 6 种类型，没有别的花样：

| 类型 | 举例 | 说明 |
| --- | --- | --- |
| 数字 | 1、1.7、-3 | 不区分整数和小数 |
| 布尔 | true 或 false | 只有这两个，不能加引号 |
| 字符串 | "你好"、"hello" | 必须用双引号包裹 |
| 对象 | {"name":"张三"} | 用花括号 {} 包裹 |
| 数组 | [1, 2, 3] | 用方括号 [] 包裹 |
| null | null | 表示“空”，单独一类 |

---

## **最容易踩的坑**

只有字符串两侧需要加双引号，其他类型统统不要加！

一旦加错，游戏或程序解析时会报错，或者得到完全错误的结果。

举例：
❌ "false" —— 这是字符串，不是布尔值！
✅ false —— 这才是布尔值。

> 一个经典陷阱："false" 被强行当作布尔解析时，会变成 true（因为非空字符串为真），这会导致逻辑完全反掉！

## 括号问题也要注意

JSON 使用两种括号：

- 花括号 {} 用来包裹 对象（即一组键值对）
- 方括号 [] 用来包裹 数组（即一组有序的值）

使用括号时，必须成对出现，而且不能混用。常见错误包括：

| 错误写法 | 正确写法 | 说明 |
| --- | --- | --- |
| {"name": "张三" | {"name": "张三"} | 缺少右花括号 |
| ["a", "b" | ["a", "b"] | 缺少右方括号 |
| [{"name": "张三"]} | [{"name": "张三"}] | 对象和数组嵌套时必须按顺序各自闭合 |

这些错误这样直接摆出来，看上去很明显.

但如果代码和括号嵌套比较多的话，肉眼还是不太容易观察出来的.

这也就是为什么我们不推荐你使用文本编辑器

## 实战纠错（来试试手！）

下面这段 JSON 是 *错误* 的，你能找出所有问题吗？

```json
{
    "name": 任务点数,   // ❌ 期望是字符串，却没加引号
    "cost": "1",       // ❌ 期望是数字，却加了引号
    "color": 4A6949FF, // ❌ 期望是字符串，没加引号
    "alwaysUnlocked": "false" // ❌ 期望是布尔，却加了引号
}
```

---

正确答案（对照看看）

```json
{
    "name": "任务点数",
    "cost": 1,
    "color": "4A6949FF",
    "alwaysUnlocked": false
}
```
